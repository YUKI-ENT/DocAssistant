# PDFWriter

C# / WPF / .NET 10 のWindowsアプリです。Visual Studioで **PDFWriter.sln** を開き、F5で実行します。

## 基本操作

- 上のテンプレート一覧からPDFを選択するか、「PDFを開く」を使います。
- 「文字入力」でクリックして入力します。空白だけの文字枠は、フォーカスを離したときや別の場所をクリックしたときに消えます。
- フォント・文字サイズは、追加前、入力中、または文字枠を選択した状態で変更できます。
- 「文字・描画の色」で黒・グレー・赤・オレンジ・黄・緑・青緑・青・紫・白を選べます。
  新しい文字・ペン・図形に使われます。入力中の文字、または「選択・移動」で選択した文字・手書き・図形の色も変更できます。
  色は保存・印刷に反映され、Ctrl+Z/Ctrl+Yにも対応します。
- 「選択・移動」で長方形をドラッグします。選択領域と交差する文字枠・図形・手書き線の外接枠が選択対象です。
  選択枠の内側で移動、ハンドルで拡縮します。Deleteで選択項目を削除できます。文字枠は右クリックでも削除できます。
- 「ペン」で手書きします。「ペン・図形の太さ」で線幅を選びます。選択済みの手書き・図形にも適用できます。
- 「消しゴム」は手書きを線単位で消します。文字と図形は選択してDeleteを使います。
- 「長方形」「楕円」「直線」はドラッグで描画します。長方形・楕円は塗りつぶしなしです。
  描画後は自動で「選択・移動」に切り替わり、作った図形に選択枠が表示されます。そのまま移動・拡縮できます。
  続けて別の図形を描くときは、描画ツールをもう一度選びます。
  「図形の線種」で実線／点線を指定します。選択済み図形の線種も変更できます。
- Ctrl+Zで取り消し、Ctrl+YまたはCtrl+Shift+Zでやり直し。文字入力、フォント、手書き、消去、図形、移動、拡縮、削除が対象です。
  文字は約0.7秒の入力休止で履歴をまとめます。履歴は最大約79操作、メモリ量に応じて古い履歴から整理します。
  別文書を開くと履歴はリセットされ、履歴自体はファイルに保存しません。
- 「保存」またはCtrl+Sで .pdfwrite に保存します。「編集を開く」で再開できます。
- 「印刷 / PDF出力」でプリンターを選択します。PDF保存は Microsoft Print to PDF を選びます。
  紙に手書きする場合は「手書き・図形も印刷」を外すと、文章と元の用紙だけを印刷できます。

## 設定

右上の「設定」で以下を変更できます。

- 既定の保存先：編集データの保存・読み込みダイアログの初期フォルダ。
- テンプレートフォルダ：フォルダ直下のPDFをコンボボックスに表示。
- 個別PDF登録：別フォルダのPDFも追加できます。登録解除はPDF本体を削除しません。
- 起動時テンプレート：「表示しない」または登録済みPDFを選択。

PDF本体は移動・コピーしません。登録ファイルを移動した場合は再登録してください。
設定は %LOCALAPPDATA%/PDFWriter/settings.json に保存します。
初回はソリューションのあるフォルダをテンプレートフォルダとして使います。

## 右列のカルテ情報（自動表示）

起動時に、COMで取得できる起動済みAccessを自動確認します。対象MDBの設定は不要です。
「患者マスター」が存在すれば電子カルテとして認識し、フォームが開いている場合に患者基本情報9項目を右列へ表示します。
AccessやMDBを自動で開くことはありません。未起動時は約2秒間隔で再確認し、電子カルテ検出後は読み取り完了から約750ms後に更新します。
右列の文字を選択してCtrl+Cでコピーできます。同じ内容の更新では選択を維持します。
フォームを閉じた場合、新規レコード、取得失敗時は以前の患者情報を消します。
Accessが25秒間応答しない場合は監視を停止します。Access側の状態を確認後、「再取得」で監視を再開してください。
右列の情報は編集PDF・設定・ログへ自動保存しません。
診療記録は「患者マスター / 受診カルテサブ」のRecordsetCloneから症状と指示欄を読みます。
症状・所見の下に投薬・処置（指示欄）を表示し、それぞれ独立したスクロール欄に収めます。症状が空で指示欄だけがある行も取得します。
既存クエリの表示期間・絞り込みに従い、受診日を新しい順、同一受診の記載を「順番」の昇順で表示します。
カルテ番号の商（10で割った整数部分）が同じ枝番を含め、見出しに枝番を表示します。別の患者番号の記録が混ざる場合は本文の表示を中止します。
本文は約5秒ごとに再取得し、「再取得」ボタンは待ち時間を省いて読み直します。選択範囲は本文が変わらない間維持します。
大量の記録はGetRowsでまとめて読み、クエリ順の末尾5,000行を上限として、上限に達した場合は右列に明示します。
Accessの表示位置・絞り込み・保存状態は変更しません。編集中の未保存内容は取得を保証せず、保存済みのレコードを表示します。
本文の取得失敗時は本文を消し、患者番号を再確認できた場合は基本情報の表示を続けます。
複数のAccessを同時に起動している場合、GetActiveObjectが返す1インスタンスが対象です。

## Access カルテ連携（接続診断）

Accessがインストールされた電子カルテ端末で使用します。

1. メイン画面の「Access カルテ連携」を開きます。
2. 「MDBを選択…」でクライアントMDB（例：DYNA_cnt_ons.mdb）を指定します。
3. Access側でカルテを開き、対象フォーム名を「患者マスター」にして「開いているAccessに接続」を押します。未起動の場合は「MDBを開く・接続」も使えます。
4. Access側にログイン画面・リンク先接続などが出た場合は、通常どおりAccess側で操作します。
5. フォームが未表示の場合は、カルテ画面を開いて「再読み込み」を押します。
   「対象フォームを開く」からAccessのOpenFormを呼ぶこともできます。この場合はフォームの通常の起動イベントが実行されます。
6. 項目名・種類・ControlSource・サブフォーム元を確認します。「構造をコピー」で一覧をJSONとしてクリップボードにコピーできます。

MDBのパスとフォーム名をアプリ設定に記憶します。ファイルの指定だけでは起動せず、「開く・接続」でCOM経由の接続／起動を行います。
取得後に入力パスを変更したり接続に失敗した場合は、前の構造一覧を消去します。
開いているサブフォームは階層をたどります（最大8階層、3000項目）。未読込のサブフォームは注記します。
「現在の患者情報を取得」で、患者マスターの氏名・フリガナ・性別コード１・カルテ番号・郵便番号・住所１・住所２・TELのValueを素材欄へ表示します。性別は1＝男、2＝女として表示します。生年月日は現在の患者レコードの「年号・生年・月・日」から和暦で表示します。素材は編集・コピーできます。この連携診断ウィンドウでは患者変更後に再取得してください（メイン画面の右列は自動更新）。取得途中のカルテ番号変更はエラーにして結果を破棄します。値は設定やログへ保存しません。ID移動・LLM送信は未対応です。カルテ本文はメイン画面の右列で自動取得します。
COM参照は専用のSTAスレッドで扱い、画面を閉じてもAccessにはQuitを送りません。
25秒で応答がない場合はAccess側のダイアログなどを確認して接続し直します。タイムアウトはAccess側の処理を強制終了しません。
この開発環境ではAccess未導入のため、実際のCOM接続・電子カルテでの取得は未検証です。
模擬フォームでサブフォーム探索・未表示フォーム・連結先取得を確認し、値を読み取らないことをテストしています。

## ファイル形式と制約

- 元PDFは変更せず、文字と手書き・図形を上に重ねます。PDF本文の直接編集、OCR、入力欄の自動認識は未対応です。
- .pdfwrite は元PDF・JSON・ISFを含むZIPです。暗号化はしていません。
- 旧バージョンの編集データを読み込めます。色の指定がない文字・図形は黒で表示します。新しい保存形式（Version 3）には色・フォント・図形を含むため、古い実行ファイルでは開けません。
- 印刷は用紙の印刷可能領域に合わせて縮小します。背景は約240dpiの画像で、元PDFのベクトル情報や検索可能な背景文字は維持しません。
- 文字が枠に収まらない場合は枠を拡大してください。文字あふれの自動警告、パスワード入力、ページ追加削除は未対応です。
- 実機のペン、実プリンター、Visual Studioのデバッガー内での操作は利用環境でも確認してください。

PDF描画には [PDFtoImage](https://github.com/sungaila/PDFtoImage)（PDFium / SkiaSharp）を使用しています。

## 開発確認

~~~powershell
dotnet build PDFWriter.sln
./scripts/Test-Shutdown.ps1
~~~

空の画面、PDF読み込み後、補助ウィンドウ存在時、処理中の終了要求に加え、
編集機能テスト（5回）で正常終了を検証します。
編集機能テストでは、空欄削除、文字・フォント・図形・移動・削除・ペン・消去のUndo/Redo、
長方形選択、保存再開、文字のみの印刷、設定データを確認します。
tmp/smoke に結果と画面・印刷用のPNGを出力します。記入データは架空です。

## 終了時の不具合への対応

Windows.Data.Pdfの終了時にIntel igd10um64xe.DLLで停止する問題を再現したため、
PDFiumのCPUビットマップ描画へ切り替えています。
終了ログは %LOCALAPPDATA%/PDFWriter/Logs/lifecycle-<PID>.log です。
起動・終了段階のみ記録し、PDF名や入力内容は記録しません。

## 32bit Access用ビルド

Visual Studioでは PDFWriter.sln を開き、構成を Release / x86 にしてビルドしてください。
x86構成は PlatformTarget=x86、RuntimeIdentifier=win-x86 です。
Windows-x86 発行プロファイルは .NET ランタイム・PDF描画ライブラリを含む単一EXE形式です。

```powershell
dotnet publish PDFWriter/PDFWriter.csproj -p:PublishProfile=Windows-x86 -p:Platform=x86
```

発行先はルートの publish/PDFWriter。配布時は PDFWriter.exe だけをコピーしてください。
フォームの読み込みはAccess COM経由です。Jet/ACE OLE DBへの直接接続は使用しません。
Access側で使うJet 4.0やリンクテーブルの設定は変更しません。
接続先MDBのパスを照合し、別のMDBなら読み込みを拒否します。
複数のAccessを開いていると対象を取得できないことがあるため、まず対象MDBだけを開いて接続してください。
エラー欄には失敗した処理名、HRESULT、PDFWriterの実行ビット数を表示します。

## 出力フォルダ

構成は Debug / Release、プラットフォームは x86 のみです。
通常のビルド・F5は `PDFWriter/bin/Debug`、Releaseビルドは `PDFWriter/bin/Release` に出力します。
どちらも32bitランタイムを含みます。フレームワーク名・x86・win-x86の追加階層は作りません。
配布用は Windows-x86 プロファイルで発行し、ルートの `publish/PDFWriter/PDFWriter.exe` を使用してください。
他端末へは `publish/PDFWriter/PDFWriter.exe` だけをコピーしてください。通常のビルドだけでは配布版は更新されません。
旧出力は `tmp/output-backup-*` に退避しています。

単一EXEは起動時に必要な実行ファイルをユーザーの一時領域へ展開します（初回起動は時間がかかる場合があります）。PDFテンプレート・MDB・編集データは別途用意します。Access COMの実機接続は配布先でも確認してください。

未確定所見は「患者マスター / 受診症状サブフォーム」のRecordsetCloneから取得し、患者情報と症状・所見の間に表示します。
カルテ番号は枝番込みで現在の患者と一致する行だけを表示します。元データには日付がないため日付を補わず、受診コードごとに順番で並べます。
未確定所見は患者情報と同じ監視周期で更新します。フォームの保存やレコード移動は行わず、受診症状テーブルにまだ反映されていない入力途中の文字は含まれない場合があります。
未確定所見は高さ120、症状・指示欄は各180のスクロール欄です。右列全体もスクロールでき、小さい画面で各欄が数行まで縮まるのを防ぎます。

薬歴は右列の「薬歴（全枝番）」に受診日ごとに表示します。日付は新しい順で、クリックすると展開・折りたたみできます。
展開すると受診コード・枝番ごとに薬名と数量を表示し、文字を選択してコピーできます。単位・用法は推測しません。
Access COMのCurrentDbから受診投薬と受診を結ぶ読み取り専用SQLを実行し、カルテ番号の整数商（10で割った整数部分）が一致する全枝番を対象にします。
サブフォームの現在の受診や表示期間には制限せず、受診投薬に保存されている全件を読みます。別テーブルへ退避された薬歴は対象外です。
受診に結び付かない投薬も日付不明として表示します。受診側の患者番号が別患者の場合は対象外です。
薬歴は約10秒ごとに再取得し、「再取得」は即時更新します。展開状態は同じ患者番号本体の間で維持し、患者が変わる・接続が切れる・取得失敗時には以前の薬歴を消します。
薬歴のSQLはSELECTのみで、Accessのフォーム操作やデータ更新は行いません。記録は設定やログへ保存しません。
