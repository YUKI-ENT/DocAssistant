# DocAssistant

現在のリリース：**ver20260912**。

## バージョン管理

`Directory.Build.props` の `ReleaseDate` を `YYYYMMDD` 形式で設定し、`scripts/Publish-SingleFile.bat` を実行します。
画面のアプリ名の下・ウィンドウタイトルとEXEの製品バージョンに `ver20260912` の形式で反映されます。
Windows/.NET用の数値バージョンは `2026.9.12.0` です。ビルド日では自動更新せず、リリース日を明示して管理します。
編集データ内部のVersionは保存形式の番号であり、アプリのバージョンとは別です。

Visual Studioでは `DocAssistant.sln`（または `DocAssistant.slnx`）を開いてください。
設定・ログの保存先は `%LOCALAPPDATA%/DocAssistant`、配布先は `publish/DocAssistant/DocAssistant.exe` です。

C# / WPF / .NET 10 のWindowsアプリです。Visual Studioで **DocAssistant.sln** を開き、F5で実行します。

## 基本操作

- AIアシスタント・カルテ情報は見出し右の「▶」で個別に折り畳み、右側に残るタブの「◀」で開けます。入力内容や生成結果は保持され、調整した幅も起動中は記憶します。折り畳んだ分だけ文書作成領域が広がります。

- 上のテンプレート一覧からPDFを選択するか、「PDFを開く」を使います。
- 「文字入力」でクリックして入力します。空白だけの文字枠は、フォーカスを離したときや別の場所をクリックしたときに消えます。
- フォント・文字サイズは、追加前、入力中、または文字枠を選択した状態で変更できます。
- 「文字・描画の色」で黒・グレー・赤・オレンジ・黄・緑・青緑・青・紫・白を選べます。
  新しい文字・ペン・図形に使われます。入力中の文字、または「選択・移動」で選択した文字・手書き・図形の色も変更できます。
  色は保存・印刷に反映され、Ctrl+Z/Ctrl+Yにも対応します。
- 「選択・移動」で長方形をドラッグします。選択領域と交差する文字枠・図形・手書き線の外接枠が選択対象です。
  選択枠の内側で移動、ハンドルで拡縮します。Deleteで選択項目を削除できます。文字枠は右クリックでも削除できます。
- 「ペン」で手書きします。「ペン・図形の太さ」で線幅を選びます。選択済みの手書き・図形にも適用できます。
- 「消しゴム」は手書きを線単位で消します。文字と図形は選択してDeleteを使います。
- 「長方形」「楕円」「直線」はドラッグで描画します。長方形・楕円は塗りつぶしなしです。
  描画後は自動で「選択・移動」に切り替わり、作った図形に選択枠が表示されます。そのまま移動・拡縮できます。
  続けて別の図形を描くときは、描画ツールをもう一度選びます。
  「図形の線種」で実線／点線を指定します。選択済み図形の線種も変更できます。
- Ctrl+Zで取り消し、Ctrl+YまたはCtrl+Shift+Zでやり直し。文字入力、フォント、手書き、消去、図形、移動、拡縮、削除が対象です。
  文字は約0.7秒の入力休止で履歴をまとめます。履歴は最大約79操作、メモリ量に応じて古い履歴から整理します。
  別文書を開くと履歴はリセットされ、履歴自体はファイルに保存しません。
- 「保存」またはCtrl+Sで .pdfwrite に保存します。「編集を開く」で再開できます。
- 「印刷 / PDF出力」でプリンターを選択します。PDF保存は Microsoft Print to PDF を選びます。
  紙に手書きする場合は「手書き・図形も印刷」を外すと、文章と元の用紙だけを印刷できます。

## 設定

右上の「設定」で以下を変更できます。

- 既定の保存先：編集データの保存・読み込みダイアログの初期フォルダ。
- テンプレートフォルダ：フォルダ直下のPDFをコンボボックスに表示。
- 個別PDF登録：別フォルダのPDFも追加できます。登録解除はPDF本体を削除しません。
- 起動時テンプレート：「表示しない」または登録済みPDFを選択。

PDF本体は移動・コピーしません。登録ファイルを移動した場合は再登録してください。
設定は %LOCALAPPDATA%/DocAssistant/settings.json に保存します。
初回はソリューションのあるフォルダをテンプレートフォルダとして使います。

## 右列のカルテ情報（自動表示）

起動時に、COMで取得できる起動済みAccessを自動確認します。対象MDBの設定は不要です。
「患者マスター」が存在すれば電子カルテとして認識し、フォームが開いている場合に患者基本情報と注意リストを右列へ表示します。注意リストはフォームの現在のRecordsetにある「メモ」（RecordSourceの `[患者包括マスター].[メモ]`）を読み取り、改行を保持します。空欄は「未登録」、読み取りに失敗した場合は「取得できません」と表示します。患者切り替えや再取得に追従し、フォームの移動・保存は行いません。

注意リストの検証は `DocAssistant.exe --patient-test` で実行できます。実データにアクセスせず、Recordsetの読み取り、改行・空欄・取得失敗、表示更新、患者切り替えを確認します。結果は `tmp/patient-test/result.txt` に出力します。
AccessやMDBを自動で開くことはありません。未起動時は約2秒間隔で再確認し、電子カルテ検出後は読み取り完了から約750ms後に更新します。
右列の文字を選択してCtrl+Cでコピーできます。同じ内容の更新では選択を維持します。
フォームを閉じた場合、新規レコード、取得失敗時は以前の患者情報を消します。
Accessが25秒間応答しない場合は監視を停止します。Access側の状態を確認後、「再取得」で監視を再開してください。
右列の情報は編集PDF・設定・ログへ自動保存しません。
診療記録は「患者マスター / 受診カルテサブ」のRecordsetCloneから症状と指示欄を読みます。
症状・所見の下に投薬・処置（指示欄）を表示し、それぞれ独立したスクロール欄に収めます。症状が空で指示欄だけがある行も取得します。
既存クエリの表示期間・絞り込みに従い、受診日を新しい順、同一受診の記載を「順番」の昇順で表示します。
カルテ番号の商（10で割った整数部分）が同じ枝番を含め、見出しに枝番を表示します。別の患者番号の記録が混ざる場合は本文の表示を中止します。
本文は約5秒ごとに再取得し、「再取得」ボタンは待ち時間を省いて読み直します。選択範囲は本文が変わらない間維持します。
大量の記録はGetRowsでまとめて読み、クエリ順の末尾5,000行を上限として、上限に達した場合は右列に明示します。
Accessの表示位置・絞り込み・保存状態は変更しません。編集中の未保存内容は取得を保証せず、保存済みのレコードを表示します。
本文の取得失敗時は本文を消し、患者番号を再確認できた場合は基本情報の表示を続けます。
複数のAccessを同時に起動している場合、GetActiveObjectが返す1インスタンスが対象です。

## Access カルテ連携（接続診断）

Accessがインストールされた電子カルテ端末で使用します。

1. メイン画面の「Access カルテ連携」を開きます。
2. 「MDBを選択…」でクライアントMDB（例：DYNA_cnt_ons.mdb）を指定します。
3. Access側でカルテを開き、対象フォーム名を「患者マスター」にして「開いているAccessに接続」を押します。未起動の場合は「MDBを開く・接続」も使えます。
4. Access側にログイン画面・リンク先接続などが出た場合は、通常どおりAccess側で操作します。
5. フォームが未表示の場合は、カルテ画面を開いて「再読み込み」を押します。
   「対象フォームを開く」からAccessのOpenFormを呼ぶこともできます。この場合はフォームの通常の起動イベントが実行されます。
6. 項目名・種類・ControlSource・サブフォーム元を確認します。「構造をコピー」で一覧をJSONとしてクリップボードにコピーできます。

MDBのパスとフォーム名をアプリ設定に記憶します。ファイルの指定だけでは起動せず、「開く・接続」でCOM経由の接続／起動を行います。
取得後に入力パスを変更したり接続に失敗した場合は、前の構造一覧を消去します。
開いているサブフォームは階層をたどります（最大8階層、3000項目）。未読込のサブフォームは注記します。
「現在の患者情報を取得」で、患者マスターの氏名・フリガナ・性別コード１・カルテ番号・郵便番号・住所１・住所２・TELのValueを素材欄へ表示します。性別は1＝男、2＝女として表示します。生年月日は現在の患者レコードの「年号・生年・月・日」から和暦で表示します。素材は編集・コピーできます。この連携診断ウィンドウでは患者変更後に再取得してください（メイン画面の右列は自動更新）。取得途中のカルテ番号変更はエラーにして結果を破棄します。値は設定やログへ保存しません。ID移動・LLM送信は未対応です。カルテ本文はメイン画面の右列で自動取得します。
COM参照は専用のSTAスレッドで扱い、画面を閉じてもAccessにはQuitを送りません。
25秒で応答がない場合はAccess側のダイアログなどを確認して接続し直します。タイムアウトはAccess側の処理を強制終了しません。
この開発環境ではAccess未導入のため、実際のCOM接続・電子カルテでの取得は未検証です。
模擬フォームでサブフォーム探索・未表示フォーム・連結先取得を確認し、値を読み取らないことをテストしています。

## 紹介状の入力補助

- 「紹介状作成」タブで、表示中患者の紹介状を紹介番号の新しい順に取得します。カルテ番号は一の位の枝番をまとめ、前・次ボタンで過去の紹介状を表示します。
- 「新規」は今日付の空の下書き、「コピーして新規」は表示内容を引き継ぐ今日付の下書きです。新規では現在表示中患者の枝番を使用し、既存紹介状の編集では元の枝番を保持します。下書きの段階ではAccessへ書き込みません。
- 紹介先1・紹介先2・紹介先先生は直接入力と前方一致の自動補完に対応します。候補は全患者の紹介状から空欄を除いて集計し、使用回数の多い順に並べます。候補取得が失敗しても直接入力できます。
- 保存処理は起動中AccessのDAOを使って「紹介状」テーブルの1レコードを更新する構成です。紹介状フォームの開閉・入力・採番処理は呼び出しません。フォーム側の中断時処理との干渉を避けるため、同フォームが開いている間は保存しません。印刷はAccess側で行います。
- 紹介番号は長整数型で、提供された `SHOUKAIJOU()` と同じ「全体の末尾番号+1、空なら1」の規則で保存時に採番します。本アプリは紹介状テーブル全体の最大番号を使用し、患者で絞り込んだ最大値や画面の並び順には依存しません。紹介番号単独の一意インデックスを確認し、重複キーエラーの場合だけ最大値を取り直して最大3回試行します。一意インデックスが確認できない場合や長整数型の上限では登録を止め、テーブル定義は自動変更しません。
- 日付はDateTime、検査結果は長いテキストに対応します。他の入力項目もテーブルの型と文字数を保存前に確認します。紹介状追加・紹介状薬名・紹介状病名テーブル、およびフォーム内の採番・転記処理は呼び出しません。コピー対象は本アプリに表示する紹介状テーブルの項目です。
- MDBパス・表示中患者・紹介番号・枝番を保存前に照合します。他で変更された紹介状は上書きせず、保存中の失敗時は下書きを保持します。保存結果が不明な場合は再取得まで再保存を止めます。患者切替時も未保存の下書きを保持し、対象患者が一致しない間は保存できません。
- 下書きはメモリ内だけで保持します。破棄・終了時には未保存の変更を確認します。実際のAccessや患者データへの保存は未検証です。

架空データによる確認は `DocAssistant.exe --referral-test` で実行します。実MDBへ接続・書き込みせず、履歴、患者照合、競合、失敗時の処理、画面を確認します。

## ファイル形式と制約

- 元PDFは変更せず、文字と手書き・図形を上に重ねます。PDF本文の直接編集、OCR、入力欄の自動認識は未対応です。
- 「PDF出力」はプリンタを使わず、元PDFの文字・ベクトル情報を保持したPDFを保存します。ページサイズ・回転・切り抜き領域も維持します。書き込みは透明画像（通常300dpi、大判ページはメモリ使用量に応じて調整）として重ねるため、追加した文字は検索・選択できません。
- 「手書き・図形も出力」はPDF出力と印刷の両方に適用します。オフの場合も追加文字は出力します。「保存」は再編集用の .pdfwrite を保存する操作です。PDF出力だけでは編集データを保存した扱いにはしません。
- .pdfwrite は元PDF・JSON・ISFを含むZIPです。暗号化はしていません。
- 旧バージョンの編集データを読み込めます。色の指定がない文字・図形は黒で表示します。新しい保存形式（Version 3）には色・フォント・図形を含むため、古い実行ファイルでは開けません。
- 印刷は用紙の印刷可能領域に合わせて縮小します。背景は約240dpiの画像で、元PDFのベクトル情報や検索可能な背景文字は維持しません。
- 文字が枠に収まらない場合は枠を拡大してください。文字あふれの自動警告、パスワード入力、ページ追加削除は未対応です。
- 実機のペン、実プリンター、Visual Studioのデバッガー内での操作は利用環境でも確認してください。

PDF描画には [PDFtoImage](https://github.com/sungaila/PDFtoImage)（PDFium / SkiaSharp）、直接PDF出力には [PDFsharp](https://github.com/empira/PDFsharp)（MITライセンス）を使用しています。

## 終了時の不具合への対応

Windows.Data.Pdfの終了時にIntel igd10um64xe.DLLで停止する問題を再現したため、
PDFiumのCPUビットマップ描画へ切り替えています。
終了ログは %LOCALAPPDATA%/DocAssistant/Logs/lifecycle-<PID>.log です。
起動・終了段階のみ記録し、PDF名や入力内容は記録しません。

## 32bit Access用ビルド

Visual Studioでは DocAssistant.sln を開き、構成を Release / x86 にしてビルドしてください。
x86構成は PlatformTarget=x86、RuntimeIdentifier=win-x86 です。
Windows-x86 発行プロファイルは .NET ランタイム・PDF描画ライブラリを含む単一EXE形式です。

```powershell
dotnet publish DocAssistant/DocAssistant.csproj -p:PublishProfile=Windows-x86 -p:Platform=x86
```

発行先はルートの publish/DocAssistant。配布時は DocAssistant.exe だけをコピーしてください。
フォームの読み込みはAccess COM経由です。Jet/ACE OLE DBへの直接接続は使用しません。
Access側で使うJet 4.0やリンクテーブルの設定は変更しません。
接続先MDBのパスを照合し、別のMDBなら読み込みを拒否します。
複数のAccessを開いていると対象を取得できないことがあるため、まず対象MDBだけを開いて接続してください。
エラー欄には失敗した処理名、HRESULT、DocAssistantの実行ビット数を表示します。

## スクリプトで単一EXEを作成

.NET 10 SDKをインストールしたWindowsで、リポジトリのルートから実行します。

```powershell
.\scripts\Publish-SingleFile.bat
```

PowerShellの実行ポリシー変更は不要です。バッチファイルから直接dotnetを実行します。
Release / win-x86で発行し、`publish/DocAssistant/DocAssistant.exe` を更新します。
.NETランタイムとネイティブライブラリを含みます。PDFテンプレート・MDB・編集データは別途用意します。

AIアシスタントの検査・注射の履歴は、それぞれ `受診検査`（`検査項目名`）・`受診注射`（`薬名`）を `受診` と結合して取得します。
既存の投薬・処置と同様に、カルテ番号・受診コード・順番・数量が必要です。対象期間と当日表示の優先規則も共通です。

## 出力フォルダ

構成は Debug / Release、プラットフォームは x86 のみです。
通常のビルド・F5は `DocAssistant/bin/Debug`、Releaseビルドは `DocAssistant/bin/Release` に出力します。
どちらも32bitランタイムを含みます。フレームワーク名・x86・win-x86の追加階層は作りません。
配布用は Windows-x86 プロファイルで発行し、ルートの `publish/DocAssistant/DocAssistant.exe` を使用してください。
他端末へは `publish/DocAssistant/DocAssistant.exe` だけをコピーしてください。通常のビルドだけでは配布版は更新されません。
旧出力は `tmp/output-backup-*` に退避しています。

単一EXEは起動時に必要な実行ファイルをユーザーの一時領域へ展開します（初回起動は時間がかかる場合があります）。PDFテンプレート・MDB・編集データは別途用意します。Access COMの実機接続は配布先でも確認してください。

未確定所見は「患者マスター / 受診症状サブフォーム」のRecordsetCloneから取得し、患者情報と症状・所見の間に表示します。
カルテ番号は枝番込みで現在の患者と一致する行だけを表示します。元データには日付がないため日付を補わず、受診コードごとに順番で並べます。
未確定所見は患者情報と同じ監視周期で更新します。フォームの保存やレコード移動は行わず、受診症状テーブルにまだ反映されていない入力途中の文字は含まれない場合があります。
未確定所見は高さ120、症状・指示欄は各180のスクロール欄です。右列全体もスクロールでき、小さい画面で各欄が数行まで縮まるのを防ぎます。

薬歴は右列の「薬歴（全枝番）」に受診日ごとに表示します。日付は新しい順で、クリックすると展開・折りたたみできます。
展開すると受診コード・枝番ごとに薬名と数量を表示し、文字を選択してコピーできます。単位・用法は推測しません。
Access COMのCurrentDbから受診投薬と受診を結ぶ読み取り専用SQLを実行し、カルテ番号の整数商（10で割った整数部分）が一致する全枝番を対象にします。
サブフォームの現在の受診や表示期間には制限せず、受診投薬に保存されている全件を読みます。別テーブルへ退避された薬歴は対象外です。
受診に結び付かない投薬も日付不明として表示します。受診側の患者番号が別患者の場合は対象外です。
薬歴は約10秒ごとに再取得し、「再取得」は即時更新します。展開状態は同じ患者番号本体の間で維持し、患者が変わる・接続が切れる・取得失敗時には以前の薬歴を消します。
薬歴のSQLはSELECTのみで、Accessのフォーム操作やデータ更新は行いません。記録は設定やログへ保存しません。
# AIアシスタント

カルテ情報の左にAIアシスタントのペインを追加しています。ウィンドウの既定幅は1740、最小幅は1380です。列の境界をドラッグして幅を変更できます。

1. LLMサーバー側でOpenAI互換APIを有効にします。
2. アドレスとポートを入力します。例：Ollamaは `http://localhost` / `11434`、LM Studioは `http://localhost` / `1234`。アドレスには `/v1` を含めても省略しても構いません。
3. 「モデル取得」でモデルを選択します。最後に生成に成功したモデルを保存し、次回起動時とモデル一覧取得時の既定にします。認証が必要なサーバーにはAPIキーを入力してください（ディスクには保存しません）。
4. 「今回の送信文」を自由に編集します。定型文を使う場合は、選択後に「定型文を入力欄へ」を押します。定型文の名前と本文は「定型プロンプトを編集」内の「保存」で登録でき、「追加」「削除」で管理できます。
5. 「カルテ情報を添付（ペイロード）」がONの場合は「添付するカルテ情報」を開き、所見・投薬・処置・検査・注射と共通の開始日を指定します。対象は開始日から今日までです。
6. 「送信」で実行します。添付ONでは最新の保存済みデータを読み直して送信文に添付します。OFFではAccessへの接続やカルテ更新待ちを行わず、入力欄の文章だけを送信します。結果はコピー、または選択してPDFへドラッグできます。

結果を英訳・修正する場合は「前の結果を入力欄へ」を押します。結果が入力欄に入り、カルテ添付は自動でOFFになります。先頭に「以下を英訳してください」などを追記して送信してください。過去の会話や定型文は自動添付されません。「クリア」で入力を消して新しい話題を始められます。今回の送信文と生成結果はディスクへ保存しません。

APIは `GET /v1/models` と `POST /v1/chat/completions`（非ストリーミング）です。生成中もPDF編集が可能で、「中止」で通信をキャンセルできます。応答待ちは最大5分です。接続先へのHTTPリダイレクトには追従しません。

所見はAccessの受診カルテサブに表示された保存済み記録（既存の最大5,000行）を使用します。投薬と処置はそれぞれ `受診投薬` と `受診処置手術` を `受診` と結合し、表示患者の全枝番を読み取り専用で取得します。処置には `行為名`、その他に既存薬歴と同様の受診コード・カルテ番号・順番・数量を必要とします。実際のデータベースに対応テーブルやフィールドがない場合は送信せずエラーを表示します。開始日から今日まで両端を含みます。当日の日付・受診コードが一致する受診は、履歴本文の長さや確定状態によらず、当日表示の所見・投薬・処置・検査・注射を優先します。同じ受診の保存済みデータは空でない当日表示に置き換えます。当日表示が正常に取得できて空の場合は保存済み履歴を保持します。別受診のデータも保持します。出典にも当日表示を優先した旨を付記します。当日データの取得失敗時は送信を止めます。日付が確認できない受診や、Accessのレコードにまだ反映されていない編集中の文字列は対象外です。過去の混在した指示欄を投薬や処置として推測分類することはありません。

添付ONのカルテ情報は、選んだ記録と期間・出典を含むJSONです。記録に含まれるカルテ番号なども指定先へ送信されます。患者表示が変わるか取得できなくなった場合、その患者の情報を使う通信を中止し、生成結果とその結果から取り込んだ送信文をクリアします。カルテ情報を使わない通常のチャットは継続できます。定型文の編集は「定型文を入力欄へ」で今回の送信文へ反映し、再起動後も定型文を残すには「保存」を押します。

検証：`DocAssistant.exe --llm-test` で外部通信なしのAPIモック・期間フィルター・患者切り替え・設定保存形式と画面描画を検証します。結果は `tmp/llm-test/result.txt`、画面は `tmp/llm-test/window.png` に出力します。

互換API仕様：[Ollama](https://docs.ollama.com/api/openai-compatibility)、[LM Studio](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)。
